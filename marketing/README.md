# BiBoTracking — marketing assets

## Site build (multi-language)

The landing page is generated into 7 locales (en + zh, ja, vi, id, fr, es).

- **Sources (edit these):** `src/template.html` (the page with `{{key}}` placeholders)
  and `src/i18n/<code>.json` (185 string keys per locale). `en.json` is the source of
  truth; keep all locales key-for-key in sync.
- **Generate (per environment):**
  - `node build.mjs` *or* `node build.mjs staging` → `site/` (committed). Base
    `https://staging.example.com`, **no** Google Analytics.
  - `node build.mjs production` → `site-prod/` (gitignored, built at deploy time). Base
    `https://bibotracker.com`, Google Analytics `G-EKVNL0JY98`.
  - Each writes `index.html` (en, root) + `<code>/index.html` per locale + `sitemap.xml` +
    `robots.txt`, injecting the per-locale `<html lang>`, canonical, `hreflang`/`x-default`,
    `og:locale`, JSON-LD url, and the nav language switcher.
  - Env config lives in the `ENVS` map at the top of `build.mjs` (base URL, GA id, output dir).
    Overridable ad hoc via `SITE_BASE_URL` / `SITE_GA_ID` / `SITE_OUT` env vars.
- **Host-agnostic links:** the language switcher uses **root-relative** hrefs (`/`, `/zh/`…)
  and all asset/stylesheet refs are root-relative (`/styles.css`, `/assets/…`) so locale
  subpages (`/zh/`, `/ja/`…) load CSS/images and language switching works on any host. Only
  SEO-facing URLs (canonical/og/hreflang/JSON-LD/sitemap) are absolute and env-specific.
- **Do NOT hand-edit `site/` or `site-prod/`** — they are generated. Edit the template/JSON
  and re-run. The deploy scripts regenerate automatically: `deploy/build.sh` (staging) runs
  `build.mjs staging`; `deploy/build-prod.sh` (production) runs `build.mjs production` and
  overlays it over the committed static assets.

## Blog (English only)

The blog at `/blog/` is **English only** — the 7-locale setup above covers the landing page,
not the blog. Posts are markdown files with YAML front matter:

```
marketing/blog/posts/<slug>.md      # one file per post; the file name IS the URL slug
marketing/blog/assets/<file>        # images used by posts, served at /blog/assets/<file>
```

The slug must be lowercase `a-z`, `0-9` and hyphens only. `my-post.md` becomes
`https://bibotracker.com/blog/my-post/`.

### Front matter

Delimited by `---` on the first line and after the last field. Everything below it is the
post body in markdown.

| Field | Required | Type | Notes |
|---|---|---|---|
| `title` | yes | string | The `<h1>` and `<title>`. Quote it. Keep under ~60 chars for SEO. |
| `description` | yes | string | Meta description + OG/Twitter description + the blurb in the list. 120–160 chars. |
| `date` | yes | `YYYY-MM-DD` | Publication date. Drives the ordering of `/blog/` (newest first). |
| `updated` | yes | `YYYY-MM-DD` | Last meaningful edit. Same as `date` for a new post. Used for `lastmod` in the sitemap. |
| `tags` | yes | list of strings | Lowercase, hyphenated, e.g. `[time-tracking, remote-work]`. Used for related posts. |
| `focus_keyword` | yes | string | The one phrase the post targets. Use it in the title, the first paragraph and one H2. |
| `cover` | no | root-relative path | e.g. `/blog/assets/my-post.png`. Used as the OG image; falls back to the site OG image when absent. |

Example:

```yaml
---
title: "Free Hubstaff alternative: what to look for"
description: "A practical checklist for replacing Hubstaff without paying per seat, and where the free options actually fall short."
date: 2026-10-27
updated: 2026-10-27
tags: [time-tracking, alternatives]
focus_keyword: "free hubstaff alternative"
cover: /blog/assets/hubstaff-alternative.png
---
```

### Body conventions

- **No `# Title` in the body** — the title comes from the front matter.
- Sections use `##`, sub-points `###`.
- Internal links are root-relative (`/#pricing`, `/blog/other-post/`); external links are absolute.
- Images use `/blog/assets/<file>` and always have alt text.
- Fenced code blocks carry a language tag.

### Conventions the build must honour

- A file whose name starts with `_` (e.g. `_example.md`) is a template or draft and is **not**
  rendered or listed. `_example.md` is the reference post — copy it to start a new one.
- `marketing/blog/posts/` is the only source of truth for posts. The rendered HTML under
  `site/blog/` is generated — **do not hand-edit it**, same rule as the rest of the site.

## Suggested copy

- **Tagline:** Local-first time & activity tracking for macOS.
- **Sub:** See where work time goes — app usage, keystrokes, screenshots, and
  browser time — all stored on the machine, exported on your terms.
- **Feature blurbs:**
  - **App & window time** — idle-aware, so only active time counts.
  - **Keyboard activity** — counts only; the actual keys are never recorded.
  - **Periodic screenshots** — automatic, with retention limits.
  - **Browser pages & time** — via a lightweight extension.
  - **100% local** — no cloud, no account; export to CSV or JSON anytime.
  - **Menu bar** — start/stop and at-a-glance status (green / amber / red).

> Design note: flat, low-color, one accent — keep marketing visuals consistent with
> the app's quiet utilitarian style.
